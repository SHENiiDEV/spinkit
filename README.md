# SpinKit — RGS-сервер и игровой хаб для Social Casino

Автономный **Remote Game Server (RGS)** с API в духе игровых агрегаторов, лобби и **100 HTML5-слотами** на трёх механиках (7 математических шаблонов + 93 скина). Клиент игр сделан в стиле Pragmatic Play: панель CREDIT / BET, настройка ставки, автоигра, быстрый спин, покупка бонуса, заставки фриспинов, Big / Mega / Epic Win.

### Механики
- **lines** — фиксированные линии слева направо, выплата × ставка на линию (общая ставка ÷ число линий). Wild заменяет всё, кроме Scatter. Scatter платит где угодно × общая ставка.
- **ways** — 243 / 1024 способа: символ на соседних барабанах с первого, в любой позиции. Выигрыш = выплата × coin value × число способов. В фриспинах Cyberpunk вайлды получают множители ×2/×3/×5 (перемножаются в одном способе).
- **giants** — ways на любой сетке (в том числе с разной высотой барабанов: `reel_heights`, например 2-4-5-6-5-4-2) с высокими символами-гигантами (например, 1×3). Гигант считается одним символом на своём барабане. Во фриспинах гигант, который выпал **целиком** (вся высота видна на экране), становится **липким** до конца фичи и получает случайный множитель из `free_spins.sticky_multipliers` (в Enchanted Knight: Knight Wild ×1…×500, Princess ×2/×3; таблицу можно задать на каждый символ). Гигант, обрезанный краем экрана, платит, но не липнет. Гигант с `height: 'reel'` (Totem Wild в Tiki Titans) лежит на ленте одной клеткой и, выпав, растягивается на весь барабан — поэтому всегда виден целиком и во фриспинах всегда липнет. Способы через гиганта с множителем умножаются на него, несколько множителей в одном способе перемножаются.
- **matchlines** — большое поле (например 7×8). 3+ одинаковых символа подряд по горизонтали или вертикали в любом месте — это линия, она платит, символы исчезают, падают новые. Множитель выигрыша: в базовой игре x1, +1 после каждого каскада (сброс каждый спин); во фриспинах начинается с x2 и растёт только чётными шагами +2 (x2, x4, x6 …), не сбрасывается до конца фичи; максимум x1024 (`multiplier`).
- **holdwin** — обычные линии + монеты с суммами (x ставки). 6+ монет запускают Hold & Win: монеты фиксируются, 3 респина, каждая новая монета сбрасывает счётчик на 3. Спецмонеты бонуса: COLLECT (собирает суммы всех монет), BOOST (удваивает все монеты). Монеты-джекпоты MINI/MINOR/MAJOR (названия задаются в `jackpot_names`), всё поле заполнено — GRAND. Бонус целиком считается в одном спине, клиент проигрывает шаги. Значения монет масштабируются вместе с paytable (`coin_scale`).
- **megaways** — на каждом барабане от 2 до 7 символов (высоты выпадают по весам `heights` / `fs_heights`), способов = произведение высот, до 117 649. Выигрыш как у ways (3+ барабана слева, WILD заменяет). Выигравшие символы исчезают, остальные падают, сверху добавляются новые. Множитель выигрыша начинается с x1 и растёт на +1 после каждого каскада; в базовой игре сбрасывается каждый спин, во фриспинах (`free_spins.persistent_multiplier`) — не сбрасывается до конца фичи.
- **clusters** — кластеры от 5 одинаковых символов, соединённых по горизонтали/вертикали, + tumble. Клетка, где взорвался выигрышный символ, помечается; повторный выигрыш на ней делает её множителем x2, дальше x4, x8 … до `spots.max` (x1024). Выигрыш кластера умножается на сумму множителей под ним. В базовой игре клетки сбрасываются после спина, во фриспинах (`free_spins.sticky_spots`) остаются до конца фичи.
- **tumble** — 8+ одинаковых символов в любом месте поля. Выигрышные символы взрываются, сверху падают новые, каскад продолжается, пока есть выигрыши. Символы-множители суммируются и умножают выигрыш всей последовательности. В Olympus они во фриспинах копятся в общий множитель.

### Общие правила платформы
- Серверный криптографический RNG (`node:crypto`), вся математика только на сервере.
- Лимит максимального выигрыша (`max_win_x`) на спин и на весь раунд фриспинов.
- Ретриггеры фриспинов с лимитом `max_spins`.
- **Feature Buy** — мгновенная покупка фриспинов, цена откалибрована на ~96% RTP.

## 💵 Деньги, баланс и ставка (как у Pragmatic)

Все суммы в API и БД — **целые числа в минимальных единицах** (центах). `10 000 000` = **$100 000.00**.

- Валюта задаётся в `src/config.js` или через переменные окружения:
  `SPINKIT_CURRENCY=EUR SPINKIT_CURRENCY_SYMBOL=€ node src/server.js`
- **Общая ставка = coin value × bet multiplier**. Coin values: $0.01 … $5.00. Множитель равен числу линий для lines-игр и 20 для ways/tumble. Для большинства игр это даёт ставки **$0.20 … $100.00**, по умолчанию **$2.00**.
- `game_config.bet_steps` — полная лестница ставок; сервер принимает только эти значения.

## 🛡️ Back Office (`/admin`)

- **Dashboard** — ставки, выигрыши, GGR, фактический RTP, игроки онлайн, график по дням, топ игр, сводка по мерчантам, последние джекпоты.
- **Merchants** — казино-операторы. У каждого: свои **API-токены** (создание и отзыв, токен показывается один раз), **валюта**, **float-баланс**, **IP whitelist** (IP и CIDR), **подпись запросов HMAC**, **лимиты ставок**, **лимит максимального выигрыша**, **RTP-профиль**, включение и выключение игр, **джекпоты**, страница интеграции с примерами curl.
- **Игры мерчанта по коллекциям:** «With artwork» (нарисованный автомат и символы) и «Basic» (процедурные барабаны с эмодзи) — у каждой счётчик и кнопки «включить/выключить всё»; плюс фильтры по механике, теме и поиску с массовыми действиями над показанными играми. В Merchant API у игры есть поле `collection` (`artwork` | `basic`) и фильтр `/api/v2/games?collection=artwork`; в лобби игры с графикой идут первыми и есть фильтр «With artwork».
- **Players** — поиск, баланс, корректировка баланса с причиной, блокировка, пометка «тестовый», история раундов и кошелька.
- **RTP Manager** — RTP по мерчантам и по играм, тестовые QA-сессии, активные сессии с кнопкой завершения.
- **Jackpots** — 4 уровня (MINI / MINOR / MAJOR / GRAND) на мерчанта: seed, must-hit-by, % отчислений, минимальная ставка, сброс, история выигрышей.
- **Rounds** — все раунды с фильтрами; для каждого раунда видны итоговая сетка, выигрыши и детали.
- **Wallet ledger**, **Audit log** (все действия админов, создание тестовых сессий, неудачные входы), **Settings** (смена пароля, пользователи с ролями owner / admin / viewer).

### RTP
Каждая игра доступна в версиях **88 / 90 / 92 / 94 / 96%**. Версия пропорционально меняет все выплаты сертифицированной таблицы; ленты, фичи и частота выигрышей остаются теми же. Выбранный RTP показывается игроку в правилах игры.
Приоритет: **настройка игры у мерчанта** › **RTP мерчанта по умолчанию**.

**QA-сессии.** Для аккаунтов с пометкой «тестовый» можно открыть сессию с любым RTP (10–300%) и принудительным бонусом на следующем спине. В игре при этом висит плашка TEST MODE, сессия записывается в аудит, депозиты тестовых аккаунтов не списываются с float, а выводить деньги им нельзя. Менять RTP конкретному реальному игроку нельзя намеренно: это обман игрока и запрещено регуляторами.

### Джекпоты (Must Hit By)
Каждая платная ставка отчисляет заданный % в пулы мерчанта. При каждом сбросе пула сервер выбирает скрытую точку срабатывания между текущей суммой и лимитом must-hit-by. Пул выпадает на том спине, который пересёк эту точку, поэтому он гарантированно разыгрывается до достижения лимита. Отчисления возвращаются игрокам полностью.

## 📡 Merchant API v2 (для казино)

Полная интерактивная документация — **`/docs`**. Кратко:

```
Authorization: Bearer sk_live_…          (+ IP whitelist, + опционально X-Timestamp / X-Signature)

GET    /api/v2/merchant                           аккаунт, float, лимиты
GET    /api/v2/games                              игры мерчанта (RTP, ставки, фичи, иконки)
GET    /api/v2/games/{game_id}                    таблица выплат и правила
POST   /api/v2/players                            создать/найти игрока {external_id, username, is_test}
GET    /api/v2/players/{external_id}              баланс
POST   /api/v2/players/{external_id}/deposit      {amount, tx_id} — идемпотентно
POST   /api/v2/players/{external_id}/withdraw     {amount, tx_id} — идемпотентно
GET    /api/v2/players/{external_id}/transactions история кошелька
POST   /api/v2/sessions                           {external_id, game_id, lobby_url} → launch_url
DELETE /api/v2/sessions/{token}                   выкинуть игрока из игры
GET    /api/v2/rounds, /api/v2/rounds/{id}        история раундов / детали для споров
GET    /api/v2/jackpots, /api/v2/jackpots/wins    пулы и выигрыши
GET    /api/v2/reports/summary, /reports/daily    GGR, RTP, разбивка по играм
```
**Подпись:** `X-Signature = hex(HMAC-SHA256(signing_secret, "{ts}.{METHOD}.{path?query}.{raw_body}"))`, `X-Timestamp` в пределах 5 минут.
**Кошелёк:** transfer-модель. Депозиты списываются с float мерчанта (если он не безлимитный), выводы возвращаются в float.

### Игровой клиент (v1, по токену сессии)
`POST /api/v1/rgs/init` · `POST /api/v1/rgs/spin` `{token, bet_amount, buy_feature}` · `POST /api/v1/rgs/refill` (только для мерчантов с бесплатными кредитами).
Ответ спина дополнительно содержит `jackpot_wins` и `jackpots`; `balance` уже включает джекпот.

### Демо-лобби (v1, без авторизации)
`POST /api/v1/games/launch` · `GET /api/v1/games` · `POST /api/v1/user/refill` · `GET /api/v1/user/balance` · `GET /api/v1/transactions`. Работают **только с игроками демо-мерчанта #1**; выключаются через `SPINKIT_PUBLIC_DEMO=0`.

## 🧩 Как добавить новую игру

Подробно — в **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)** (устройство движка и клиента, поля описания игры, как написать новую механику).

**Новая игра на готовой механике:**

```bash
npm run new-game -- --id desert_gold --name "Desert Gold" --mechanic lines   # lines | ways | tumble | giants | clusters | megaways | holdwin | matchlines
node scripts/simulate.js --game desert_gold --calibrate --write               # RTP 96% и цена Feature Buy
```

Появится `src/games/definitions/desert_gold.js` — полная копия математики эталонного шаблона (с его калибровкой, без его графики), игра сразу в лобби и в Merchant API. Меняйте символы, paytable, ленты/веса, фриспины и тему; после изменений математики — снова калибровка. Иконки символов — Twemoji из `public/games/assets/icons/` (скрипт предупредит, если для эмодзи нет SVG), своя графика — `image: '/games/<id>/assets/<file>.png'`.

**Скин (новая тема, та же математика, без калибровки):** запись в `src/games/skins/classic.js` (шаблон `base`, название, тема `look`, символы `w`, `s`, `h`, `l` по убыванию выплат) или в `src/games/skins/giants.js` для гигантов.

**Своя ИИ-графика:** `scripts/import-art.py` режет листы символов (убирает белый фон), вырезает персонажей и тотемы с тёмного фона, чистит автомат и сам измеряет окна барабанов (`theme.stage.reel_rects`) — пошагово в `docs/giant-art-prompts.md`. **Анимированный гигант:** ролик image-to-video → `import-art.py video` (убирает водяной знак со статичной рамки, режет по карточке, делает WebM + MP4 и маску) → `tall_video` / `tall_mask` у символа; клиент крутит видео в цикле на барабане и в липком гиганте. **Рескин** (та же математика, новая графика): `reskin(require('./tiki_titans'), { id, name, theme, symbols })` в `src/games/definitions/<id>.js`.

**50 игр с ИИ-графикой:** темы в `src/games/skins/ai.js`, картинки — `node scripts/gen-ai-art.js --all` (OpenAI, ключ в `.env`), нарезка — `python3 scripts/import-ai-art.py --all`; подробно в `docs/ARCHITECTURE.md`.

**Процедурная графика:** `node scripts/gen-art.js <game_id>` рисует автомат (`stage.jpg`) и символы процедурно (модули в `scripts/art/games/`), `--cover http://localhost:3000` снимает обложку для лобби из работающего сервера. Свою ИИ-графику можно подложить поверх тех же файлов (для гигантов: 1400×1254 автомат с панелью барабанов x 244, y 254, 914×853, и 400×1000 портреты). Скины с `custom_art: true` генератор не перерисовывает.

Готовая картинка всего автомата задаётся в `theme.stage` (`image`, `width`, `height`, прямоугольник барабанов `reels: {x, y, w, h}` в пикселях картинки): клиент ставит барабаны точно в панель. `theme.plainSymbols: true` рисует PNG-символы без плашек, `theme.cover` — обложка в лобби. Клиент общий для всех игр (`public/games/common/`), отдельный HTML на игру не нужен.
